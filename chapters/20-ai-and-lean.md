# 第 20 章　AI 与 Lean：自动定理证明的新时代

> 本章目标：理解为什么 AI 数学革命选择 Lean 作为"裁判"，认识 LeanDojo、AlphaProof 等标杆系统，并学会使用 AI 辅助工具写证明。

## 20.1 天作之合：AI 出主意，Lean 当裁判

大语言模型有个著名弱点：**幻觉**——它会自信地给出错误的数学证明，而且错得很优雅。怎么破？

Lean 给出了完美答案：

> **AI 负责提出证明候选，Lean 内核负责裁决对错。** 内核不疲惫、不收贿赂、不看作者名声——证明通过就是通过。

这个"生成器 + 验证器"结构是现代 AI 数学系统的通用范式：

```
┌──────────┐   候选证明    ┌──────────┐   通过 ✅/拒绝 ❌   ┌────────┐
│  AI 模型  │ ──────────▶ │ Lean 内核 │ ──────────────────▶ │ 反馈信号 │
└──────────┘              └──────────┘                      └────────┘
     ▲                                                          │
     └──────────────── 强化学习 / 搜索，利用反馈改进 ◀───────────┘
```

关键优势：

1. **奖励信号完美**：数学定理证明的"对错"由内核判定，不需要人类标注——强化学习梦寐以求的免费奖励；
2. **无幻觉输出**：系统的最终产物一定通过内核检查，可信度 100%（针对陈述本身）；
3. **难度可无限扩展**：从中学代数到费马大定理，都是同一个裁判。

## 20.2 标杆系统巡礼

### AlphaProof（Google DeepMind，2024）

强化学习系统，2024 年 IMO 达到银牌水平（与 AlphaGeometry 2 合作解出 4/6 题）。做法：把大量自然语言数学题自动翻译成 Lean 陈述，然后用 AlphaZero 式自我对弈搜索证明，Lean 提供每一步的对错反馈。DeepMind 公开表示：Lean 的**可扩展性和验证能力**是选择它的关键原因。

### LeanDojo（Caltech 等，2023）

**让机器学习模型程序化地访问 Lean** 的基础设施：

- 从 Lean 项目（如 mathlib）抽取证明数据（状态、前提、策略步骤）；
- 提供 Gym 风格的环境：AI 给出策略，环境返回新证明状态；
- 配套的 ReProver 模型展示了"检索增强证明"（从引理库检索相关定理再生成策略）的有效性。

想做"AI 定理证明"研究？LeanDojo 几乎是默认起点。

### REPL / Pantograph：机器与 Lean 对话的管道

- **Lean REPL**：把 Lean 包成交互式命令循环——喂进策略，返回状态 JSON。几乎所有"LLM 自动证明"实验都靠它（或同类工具）驱动；
- **Pantograph**：更底层的机器交互接口，支持表达式构造、符号检查，面向更精细的搜索算法（如 MCTS 证明搜索）。

### Harmonic 的 Aristotle 与其他新玩家

- **Harmonic**（由 Robinhood 联创 Tudor Achim 创立）：直接瞄准"数学超级智能"，Lean 是其验证底座；
- **AlphaProof Nexus**（2026 年公布）：DeepMind 将能力开放给研究社区，并宣布自动证明了 9 个 Erdős 问题；
- 一批开源项目（Goedel-Prover、DeepSeek-Prover、Kimina-Prover 等）在 mathlib 子集上不断刷新自动证明率——这个领域以月为单位演进。

## 20.3 亲手试试：AI 辅助的证明工作流

作为 Lean 学习者，你今天就能用上 AI 辅助。典型工作流：

### 工具一：Lean 专用搜索

- **LeanSearch / Moogle**：自然语言搜定理（"prime factorization exists" → `Nat.exists_prime_and_dvd`）；
- **Loogle**：按类型搜定理；
- **LeanExplore**：语义化搜索 Lean 声明。

这些本质是"数学搜索引擎"，背后是嵌入模型 + 索引 mathlib。

### 工具二：通用大模型 + 验证闭环

实操配方：

1. 把定理陈述写好（`theorem ... := by sorry`）；
2. 让 LLM 生成证明候选（它可能错，没关系）；
3. **贴回 VS Code 让 Lean 检查**；
4. 把报错信息喂回 LLM："目标状态是 X，你的策略报了 Y 错，请修正"；
5. 迭代直到 **No goals**。

这个"LLM + Lean 报错循环"是目前最实用的 AI 辅助姿势——LLM 负责广博的引理记忆和策略建议，Lean 负责把关。注意：**AI 说的每一句话都要过 Lean 这关才算数**，这正是这套工作流安全的原因。

### 工具三：内置自动化也是"AI"

别忘了第 10 章的自动化策略：`grind`、`omega`、`aesop`、`exact?`——它们是"符号 AI"的代表。实践中与统计 AI 互补：符号方法精确但搜索空间受限，神经网络直觉好但可能出错，**混合系统**（neuro-symbolic）是公认的方向。

## 20.4 深水区：为什么 Lean 特别适合 AI

技术层面的几个独特优势：

1. **策略即程序**：证明步骤是可执行、可组合的代码，比"自然语言证明"更适合作为动作空间；
2. **状态完全可见**：Infoview 里那个"目标 + 上下文"对机器同样是结构化数据（LeanDojo 就是抽取这个）；
3. **mathlib 是绝佳训练集**：百万行人工精写、机器验证过的数学——世界上独一无二的"高质量数学推理语料"；
4. **API 完备**：Lean 的 elaborator、metaprogramming 接口全部开放（第 17–18 章），机器可以调用人类能用的一切；
5. **自举的语言**：Lean 的工具链用 Lean 写，AI 甚至可以学习改进工具本身。

## 20.5 冷静剂：AI 还没取代证明工程师

客观看待现状：

- 自动证明在**竞赛题、教科书定理**上进展神速，但前沿数学（比如 FLT 项目的引理）仍需大量人类工作；
- 形式化一个定理的**陈述**（把自然语言数学精确写成 Lean）目前仍主要靠人——AI 翻译的陈述可能"证明了一个错误的命题"；
- 工程实践中，AI 更像"永远在线的结对伙伴"：加速查引理、补样板证明，而**架构设计、抽象选择**仍属于人类。

对学习者，这意味着：**懂 Lean 的人 + AI = 超级个体**。AI 不会取代你，但会用 AI 的 Lean 用户会取代不用的。

## 20.6 本章小结

- AI 数学的范式：**生成（模型）+ 验证（Lean 内核）**，幻觉被内核物理隔绝；
- 标杆：AlphaProof（IMO 银牌）、LeanDojo（数据与环境）、REPL/Pantograph（机器接口）；
- 今天就能用：LeanSearch/Loogle 搜定理，LLM + Lean 报错循环写证明；
- Lean 对 AI 友好的原因：策略即程序、状态结构化、mathlib 语料、API 开放；
- 未来属于"人机混合证明"——而你正在学习站在机器肩膀上的姿势。

## 练习

1. 用 LeanSearch 搜索"连续函数的复合仍连续"，对照 mathlib 中的真实定理名；
2. 选一个你会证的定理（如 `n + 0 = n` 的归纳证明），让 LLM 独立生成证明，在 VS Code 中验证——记录它错了几次、错在哪；
3. 用"报错循环"让 LLM 帮你证明：`∀ n : Nat, 2 ∣ n * (n + 1)`（n 与 n+1 必有偶数）；
4. （调研）读 LeanDojo 的论文摘要，回答：它的"前提检索"（premise retrieval）解决了什么问题？
